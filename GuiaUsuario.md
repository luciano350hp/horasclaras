# ¿De qué trata HorasClaras?

HorasClaras es un sistema pensado para que profesionales freelance —por ejemplo, profesoras de idiomas y traductoras— administren clientes, tarifas y trabajo realizado. El dominio distingue dos formas de cobrar:

- **Por hora**, para clases: se pueden registrar minutos y distinguir tiempo facturable de planificación.
- **Por palabra**, para traducciones: contempla una tarifa y un descuento para palabras repetidas.

El proyecto está hecho actualmente como **backend/API**, no como una aplicación completa con interfaz web.

## Las capas del backend

La arquitectura está organizada para que cada capa tenga una responsabilidad concreta y la lógica fluya hacia adentro:

```text
HTTP → controller → service → repository → entity / base de datos
              DTOs transportan los datos de entrada y salida
```

En el código, las carpetas de las capas son `controllers/`, `services/`, `repositories/`, `entities/` y `dtos/`. Las reglas que las rigen están en `AGENTS.md`.

| Capa | Qué hace | Ejemplo actual |
|---|---|---|
| **Controller** | Recibe las solicitudes HTTP y las delega al service. No debería decidir reglas de negocio ni hacer consultas SQL. | `cliente_controller.py` expone las rutas de clientes. |
| **Service** | Aplica reglas del dominio y decide errores como 404, 409 y 422. Devuelve DTOs. | `hora_service.py` verifica que el cliente exista y sea de tipo `hora`. |
| **Repository** | Lee y escribe datos mediante SQLAlchemy. Los `commit()` se hacen aquí. | `hora_repository.py` persiste y consulta horas. |
| **Entity** | Define las tablas y sus restricciones para la base de datos. | `cliente.py` y `hora.py`. |
| **DTO** | Define qué datos acepta y devuelve la API, con validaciones. | `cliente_dto.py` y `hora_dto.py`. |
| **Core** | Configura la aplicación y la conexión a la base. | `config.py` y `database.py`. |

`main.py` crea la aplicación FastAPI, conecta los routers y crea las tablas al iniciar. La base prevista es SQLite, y la API publica documentación interactiva en `/docs` cuando se ejecuta el servidor.

## Qué está hecho y qué no

**Implementado en el backend:**

- **CU-02: alta y gestión de clientes.** Crear, listar, consultar, actualizar y eliminar clientes, con tarifas por hora o palabra y descuento.
- **CU-03: registro de horas.** Registrar, listar, filtrar, consultar y eliminar horas. Solo acepta clientes de tipo `hora`; valida minutos positivos y los tipos `facturable` y `planificacion`.
- **Pruebas automatizadas** para clientes, horas y configuración, en `tests/`.

Los endpoints están definidos en `cliente_controller.py` y `hora_controller.py`.

**Pendiente como funcionalidad del producto:** inicio de sesión, registro de palabras y presupuestos, cálculo de montos, tarifario PDF, dashboard, lista de espera y chatbot. La planificación ya aparece como tipo de hora que se puede registrar, pero todavía no existe el cálculo que la separe del monto facturable. La tabla de casos de uso está en `README.md`.

## Cómo se construyó: OpenSpec y SDD

**SDD** significa *Spec-Driven Development*: definir qué debe hacer una funcionalidad antes de implementarla. La secuencia documentada en el proyecto es:

1. Escribir una propuesta y los requisitos del caso de uso.
2. Describir las decisiones técnicas y dividir el trabajo en tareas.
3. Implementar las capas y sus pruebas.
4. Ejecutar las pruebas y pedir una revisión.
5. Corregir lo necesario y archivar el cambio.

**OpenSpec** es la estructura y el flujo de trabajo que se usa para organizar esas especificaciones; no es una capa de la aplicación ni una base de datos. Para CU-03 hay un cambio con propuesta, diseño, tareas y escenarios en `cu-03-registro-horas/`. La configuración de sus especificaciones está en `config.yaml`.

## Skills, agentes y MCP

- **`AGENTS.md`** es el contexto general del proyecto: contiene arquitectura, convenciones, restricciones técnicas y reglas del dominio.
- **Skills** son instrucciones reutilizables para tareas específicas. Hay dos orientadas al proyecto: `crear-caso-de-uso` explica el flujo para agregar funcionalidades; `reglas-tarifas` recoge las fórmulas de cobro. También hay skills de operaciones de OpenSpec.
- **Agentes del proyecto:** `revisor.md` es de solo lectura; `backend.md` orienta el trabajo del backend; y `frontend.md` describe el rol previsto para un frontend.
- **MCP** son servidores que exponen herramientas a un agente. En la configuración actual de `opencode.json` encuentro tres: `filesystem` (local, restringido a la carpeta del proyecto), `engram` (local) y `context7` (remoto, para consultar documentación de librerías).

### ¿Qué es Gentle AI?

En este contexto, **Gentle AI no es el chatbot de HorasClaras ni una funcionalidad para sus usuarios**. Los apuntes del curso lo describen como una herramienta para configurar agentes y flujos de trabajo de desarrollo con IA; **Engram** aporta memoria de conversaciones. En la configuración de OpenCode aparecen roles relacionados con Gentle AI, como exploración, verificación y trabajo, además de otros agentes de revisión. Todo esto pertenece al **entorno usado para desarrollar el proyecto**, no a la aplicación de gestión de horas. Los apuntes lo explican en `Curso IA Engineering.md`.

## Detalles que conviene revisar

Hay algunas diferencias entre lo documentado y la configuración o el código que encontré:

- `README.md` y `PENDIENTES.md` hablan de cuatro MCP e incluyen `memory`, pero la configuración visible en `opencode.json` declara tres y no incluye `memory`.
- La documentación menciona un máximo de diez clientes, pero no veo esa validación en el service actual de `cliente_service.py`.
- Los documentos indican un descuento por repetición predeterminado de 50 %, mientras que el DTO y la entidad actuales muestran `0.00` como valor predeterminado en `cliente_dto.py` y `cliente.py`.

**En síntesis:** ya hay una API backend con clientes y registro de horas, con arquitectura por capas y pruebas. OpenSpec, skills, agentes, MCP y Gentle AI organizan cómo se desarrolla con IA; no son funcionalidades de facturación para la usuaria final. La interfaz, los cálculos, el PDF y el chatbot siguen pendientes.
